# Security Policy

## Supported versions

Security fixes are currently considered for the latest published release and the default branch.

## Reporting a vulnerability

Please do not disclose an unpatched security issue in a public GitHub issue. Contact the project maintainer privately through the contact method listed on the repository's GitHub profile or organization page. Include a description of the issue, affected version or commit, reproduction steps, and any suggested mitigation. Do not send private documents, credentials, signing keys, or personal data.

Please allow reasonable time for investigation and remediation before public disclosure. If no private contact address has been configured on GitHub, create a minimal public issue asking for a private contact channel without including vulnerability details.

## Scope notes

OpenPage is designed to operate without cloud accounts or the `INTERNET` permission. Reports involving USB device handling, document processing, local file exposure, unsafe logging, build or release secrets, and dependency vulnerabilities are relevant. Hardware compatibility problems without a security impact should be reported as ordinary issues.
